## 2. Typed families、owner 與真相

| Family／責任 | 唯一真相、authoring／formal、compiler | 保存、roots、bounds 與 writer |
|---|---|---|
| `LegacySkillFamily`（保留） | 原 `SkillId`／`SkillRevision`／`SkillDocument` 與 `SkillDraft`。原 Store latest、exact refs、flat position、舊驗證／projection 語意不變；C 的 compat frontend 可讀 exact bytes 投影，不改原執行路線。 | 原 P3-D/P4 aggregate、SavedData carrier、player_skills Attachment／journal／qualified sources 保持原格式與責任。原配額、roots、pin/reclaim 保持；不以新 family 換舊 key。 |
| `SpellDefinitionFamily` | Key＝受權的 owner scope＋family＋stable `SpellDefinitionId`。Body＝backend/category tag、activation?、settings AST、handlers、optional PhenomenonSpec、appearance、schema／provenance。每次實質作者修改只產該 Spell 自己的 immutable revision；新發布須通過完整依賴驗證。Formal 是資料，不是執行授權。 | 新 typed revision storage 與其明列唯一 persistence adapter；exact bytes／typed raw slots／versions。Latest 由 owner catalog 指定，不從最大 retained rev 推導。Current head、必要 recovery roots、具證 external exact roots／未來 leases 參與 retention；個別和 aggregate owner/server 配額另推導。 |
| `SkillManifestFamily` — `OPTIONAL_HIGH_LEVEL_DEFINITION` | 自己的 owner-scoped `SkillManifestId`／immutable `ManifestRevision`，entries 只存 Spell identity 與獨立 `ManifestEntryId`、排序／label／group／非 gameplay logical metadata。不供 Spell body 編譯、不擁有 Spell，沒有 runtime 自身 effect。 | 同一明列 new-definition publication owner 管理 typed routes，不能另立一份共享 Spell truth。Manifest body 按自己 schema、raw、quota 和 roots 驗證；非 required parent 或 publication root。若完全不用，沒有 manifest history／entries 或隱式 default manifest。 |

| Owner catalog／publication root | 同一 owner 一份 authoritative published generation：完整映射 `typed identity → exact current revision`。可以包含 Spell 及可選 Manifest routes；不是 Manifest。Generation 記錄整體 publication 順序，與 revision、actor epoch、P7 generation、P11 source epoch／version 各自獨立。 | 不可變候選與可判定的 durable commit proof 受同一 owner/writer 管理；RAM snapshot 只是目前已證實發布的 view。Recovery／retention 依真正已提交、必要待恢復資料，不能以 RAM 推耐久。 |
| Dependency／reverse index | 從當代 exact routes 與可證的 bodies 重建；只做 bounded 查詢、檢核及定位，不能自行變更 latest、授權、宣告完整 roots。 | 以 owner＋generation＋source integrity/context 綁定，失效重建或拒；可選保存 acceleration 不能成第二份 graph truth。保 coverage、work/bytes/edge limits。 |

## 3. Stable identity、revision、地址與引用

1. Spell／Manifest 身分按 family 和 owner scope 強型別隔離；名稱、顯示順序、跨家族裸 UUID/數字都不構成同一身分。已正式配發的身份不得重用；刪除／退役如後續允許，需有可證的 tombstone／no-reuse 證據。Stable handler／block identity 及其語意所在容器與 ordered statement/list 分離；dense compiler PC 只能從 exact 輸入重建，不能存成 authoring identity。
2. Exact revision key＝typed identity＋immutable revision。不改已提交 bytes，不以出版 generation、schema、actor 身分或 latest alias 代替。各 family 的 revision 配發單調性、exhaustion／overflow、staged reservation 與 crash 後不重用均須可驗；proposed revision 不等已提交。配發過的或可能已發布的身份不得因暫存／崩潰重拿；只經證明未成正式配發者才可處理為未提交 reservation。
3. `SpellIdentityReference` 只表示 owner/family scope＋`SpellDefinitionId`。Spell-to-Spell 與 Manifest-to-Spell 都採這個形狀；不寫 `latest=true`、target revision number、runtime handle 或 authorization token。Owner 是具名正規 scope，不能單信 payload 裸 ID／UUID。Owner-private 普通可發布 graph 只連本 owner 的 Spell；跨 owner 內容先獨立 fork，不建立 live edge。解析必驗 scope/身份／當下權限；跨 owner／未授權不得洩露 target 是否存在、內容或 latest。
4. 稿件可以有無法解析的 reference 材料，但不可執行；exact refs 出現在 revision address、published catalog、解析／驗證證據、export closure、未來 capture，不反寫入作者的 ordinary reference slots。已解析 historical root 若無當時可信 exact closure，不可宣稱能重演當時效果；不是讀「同 ID 現在最新」來假裝找回舊 closure。
5. Logical address 可選 standalone Spell identity；或 optional Manifest identity ＋ stable entry identity。僅定位資料與顯示，不是裝備、runtime selector、激活許可或 client 指定 revision。Editor IA：owner 的獨立 Spell 清單／單 Spell 分 activation/settings/interactions；Manifest 是另開的高階編排 view；不要求先建套組。不定按鍵、選擇、layout、拖曳、送包或 UI 實作。

## 4. Optional SkillManifest 契約

- **無 Manifest 的完整路徑**：以 owner-private Spell Draft 編寫 → 依本人 candidate catalog 驗證 → 發布獨立 Spell revision → resolver/compiler 可直接取該 Spell root／可達 graph；可分享為單 Spell closed bundle。合法的 0 activation 不阻定義存在，不等有玩家入口。以上不依賴任何組別、額外 root 或合成 SkillId。
- **有 Manifest 的完整路徑**：獨立 Spell 可先發布或與新 Manifest 在同一合法 bounded batch 中 staged。Manifest Draft → 自身與全部 entries 的依賴驗證及 Manifest revision publication → whole-Manifest availability 驗證 → 選定 stable entry → 所選 Spell 的 exact closure → 未來 compiler input。它提供順序、分類、label、group、非 gameplay logical role／presentation metadata 及分享/匯出意圖。Scope D 不採專用 Manifest appearance 欄位；如後續另採，也只作用自身顯示，不能覆寫 Spell appearance 或 gameplay。
- 每個 entry 有獨立 `ManifestEntryId`，其 scope 為所屬 Manifest identity。重排或修改 label 不更換 entry 或 Spell 身分，已退役 entry ID 不重用。
- **M-DUP（`USER_CONFIRMED / ADOPTED_IN_SCOPE`）**：同一 Manifest revision 中，`ManifestEntryId` 與所指的 Spell identity 各須唯一。同一 Spell identity 經不同 entry ID、label、group 或 order 重複出現，亦不得正式發布。Draft 可在適用 Draft／raw 限額內保留全部重複材料；reader／validator 須提供具名、有界、可定位的「重複 Manifest entry ID」與「重複 Manifest Spell identity」診斷，供作者明確修正。Formalizer／publication 拒絕違反任一唯一性條件的候選，不得自行保留第一個、最後一個、自動合併或去重。此限制只適用於單一 Manifest revision 的 entries。不同 Manifest 可各自引用同一 Spell；Spell-to-Spell graph 不受此唯一性規則約束，仍受 §5 的圖驗證與限額。日後若需要在同一 Manifest 讓同一 Spell 扮演多個角色，須另行採用 stable entry-role／binding、address、quota、UX 與 runtime 契約。
- Manifest 的全套可用性依 D-04：缺、Unknown 或不合法的 gameplay target 使該 Manifest root 整體 unavailable，raw／診斷保留，不發可執行的部分 entry bundle。正式 publication candidate 要驗全 entries；後續使用仍須核當代可用性。獨立的 Spell root 只驗自身 closure，不因被一個壞 Manifest 收錄而連坐；純視覺 Unknown 仍 fallback。
- Manifest 不保存或覆寫 Spell backend、activation、settings、handlers、PhenomenonSpec、Mana、cost、cooldown、payer 或 lifecycle。編排／metadata 變更才產新 Manifest revision；Spell head 改變須重驗受影響 Manifest，但不替其重寫 bytes／增修訂。刪除 Manifest 若後續允許，只處理其 own route／roots，**不刪任何 Spell 或 Spell revision**；移除 entry 更不授 reclaim。
- 未來從 Manifest entry 接受 root 時，同一 catalog snapshot 捕獲 exact Manifest revision、entry binding 及所選 Spell 的完整可達 exact closure；整個 Manifest 的可用性驗證不可被選中 entry 掩蓋，但未選 entries 不因此成該次 gameplay execution closure。既有 invocation／instance 不隨 Manifest 或 Spell 更新。舊 `SkillId`、原 equipped exact ref／cooldown key 均不變，不能拿來充當 `SkillManifestId` 或 `ManifestEntryId`。

## 5. 有界 owner catalog publication、耐久與 recovery

### 5.1 Prepare／validate

1. 授權 writer 在唯一 owner 路徑捕獲 exact authoritative source／base catalog generation、descriptor/registry/policy context 與配額證據。Candidate 是在此 generation 上的完整 immutable route mapping，含真正新增／修改的 Spell 或 Manifest revisions；先檢 family、owner、allocation、expected base 及所有 work/bytes limits。未修改的 bodies 保 exact 原 revision。
2. 以可證完整的 reverse-reference/closure index 找受影響 roots。至少把變更 identity、新增／刪除邊、可用性改變，以及舊／候選 graph 中傳遞引用它們的 Spell 和 Manifest 納入；不可只檢直接 callers、只信 index count 或把舊索引冒作候選。若 index 已舊、不完整或上下文改變，作有界完整驗證／重建，不能證完整便拒。受影響且未改的 caller／Manifest **重新驗證、不配新 revision**。確有內容不相容則拒整個 batch，或由正式使用者提交要改的那些 bodies 作同一合法 batch；不得自動改人內容。
3. 對候選 graph 做 identity、scope、schema、capabilities、Unknown、ref／cycle／feedback、bounds 與 compiler-front-end compatibility 全項驗證。Partition：Spell identity reference graph（可有 SCC）、runtime event feedback（另有真時序／因果預算、目前不實作）、AST 結構／compiler control-flow（無玩家 loop/procedure）、Manifest 的高階 entries（不是 callable graph）。引用閉包用 visited identity、有界 nodes/edges/depth/steps/SCC 工作量；不對 CreateSpell 遞迴 inline、不因「沒有 procedure」假定 graph 是 DAG。合法有限 SCC 不單因環而拒；缺 type/closure/可實現的有界 feedback 契約時不得稱相容。此處可要求證據／symbolic cost 需求，不發明 Scope V runtime events、費用或數值。

### 5.2 Stage／commit／讀者可見性

1. 不可變 revisions、候選 generation identity、matching graph/index 或其可重建證明、root protection、恢復所需 journal 記錄均先 staged；staged data **不屬 current**，不得以讀檔存在、dirty、save callback、mtime 或最大 revision 自行發布。權限、owner source、base generation、內容/context/bounds evidence 在唯一 commit 邊界再驗。競爭、stale source／base、unchecked partial write、任一必須驗證失敗均不得蓋過原 current。
2. Current 的切換須依**單一可恢復 publication 決定**：全部必需資料與 root/journal/durability 前件成立，且證明仍在 expected base 上，才由唯一 writer 形成該 owner 的 durable commit proof，綁 exact base/new generation 與完整 exact route/content identity。之後一次發布整個新 view，不能一個 pointer 一個 pointer 先露；讀者只能取得完整舊或完整新 generation。以這個決定為 crash/retry 的權威，不把 JVM map swap 當物理原子性。只有可證提交且正確 view 已接續才回報成功。
3. 證明未提交的失敗保留**完整舊 current graph**，staged 材料不得被看見。若 commit proof 已真耐久但 ACK 或 RAM 接續遺失，不得偽報「失敗且已退回舊 graph」，只能以同一次提交識別查明／接續；不重做、重配 revisions 或再發第二次 batch。可證提交後至 RAM view 接續前，不得從舊 view 接受新 capture 或發布。不能判定是否提交時回不可判定／隔離，阻該 owner 的 current/latest 正式讀取、新發布、新 capture 與 reclaim，保必要 root 和材料，由同一 owner 進 recovery。獨立可證的 exact 讀取／既有已接受工作不因此切換 revision；缺其本身的證據時仍依原邊界 fail-closed。這是事故處理，不是可部分發布的第三種正常狀態。

### 5.3 Recovery／root 判定與技術缺口

- 重啟只接受與 exact predecessor、owner、complete content/roots/索引證據相配的可證 publication。可證 pre-commit prefix → 舊完整 view；可證完整 committed → 同一新 view（idempotent）；證據互斥、commit 可能已成立而 body 缺失／壞損 → 隔離、保材料，不自行退到較舊頭或回 empty。已提交之 exact catalog 即使因 registry 變更使新驗證不可用，仍不是選另一個歷史 head 的許可。舊／新組件拼湊、max-revision promotion、stale worker 回寫、RAM match 清理，均不得發生。
- Retention 以完整當代 catalog 的各正式 head（包括無 Manifest、無入邊的 standalone Spell）、可證 external exact roots、publication/recovery 過程必留的 historical closures、generations／records、future accepted exact captures／pins 及各現行 legacy roots 為來源。Identity edge 只解析於對應 snapshot，不單獨 pin 同 ID 所有舊 revisions；未來 active closure 逐 exact revisions 保護，不能由今代 reverse index 重推。Manifest 刪除不及 Spell 的 head／其他 roots。Incomplete、overflow、quarantine 可能遮蔽 required roots，則停止受影響 sweep；無法安全區分責任範圍時整輪不 sweep。無可證存活 roots 與 recovery 需求、且同一 source/generation 完整再驗後，才由 sole owner 清未提交 orphan 或非 root revision；不憑時鐘老化／cache eviction 釋保護，不重用配發過的 ID。
- `TECHNICAL_GAP`：現 `SkillDefinitionStore` 的 legacy per-history CAS/`lastKey()`、18 §12 的 async save 及 §16–17 的既有 Store／Attachment 指標 journal，**沒有證成**多 definition catalog generation 的耐久整批切換。新 adapter 必須設計 exact durable writer/source 與 acknowledgement/readback/recovery evidence、可採的 physical 介質與其明確崩潰界線，再證明上述 failure/commit 狀態；物理方案由另授的 M1 依證據確定。舊 pointer journal 不能直接作 catalog commit journal，本文未授跨檔、跨 owner 或跨 world transaction。缺此證明時不啟用新正式發布；現 legacy 路徑與 P11 source/readback 規則照舊。
- `TECHNICAL_GAP`：Publication 需要 compiler front-end 相容性。M1 可證資料、索引、journal/recovery 與 stage/commit contract 的隔離路徑；若真正的前端相容性證據尚未到位，生產 new-family current publication 不得以 stub／形狀驗證就打開。C 補前端檢核和真來源證據；即使完成也不開 player/runtime。啟用前件與驗收見 §9–10。

## 6. Resolver／compiler／未來 exact capture

解析輸入只能是受權的 typed root、已證一致的 owner catalog snapshot 與 immutable revisions；candidate 驗證與已發布 current 讀分路。用 bounded visited traversal 形成 root 到所有可達 Spell identity 的 exact revision mapping，檢缺件、duplicate/scope/permission、backend ABI、Unknown、結構、feedback 和 costs。編譯純地 normalize/fold settings、規定 creation-input binder 形狀、lower 每 event 的單一有序 handler，產出 immutable program、typed operands、constants、static cost summary 及 exact source map（owner／family／SpellDefinitionId／revision ＋ stable handler/block address 對應 program-local PC；legacy 採其 typed exact ref／原位置）。不作世界讀寫或執行 effects。

Spell program key 須把所選 exact Spell root、完整 Spell closure identity 與 compiler、backend ABI、registry／validation policy context 綁定。同一 exact closure／context 可共用不可變 code/config template，無論 standalone 或經 Manifest 選取；未來每 creation 的 input/config 及動態狀態獨立。Manifest 的選取／invocation 證據另綁 exact Manifest revision、stable entry binding 與該 Spell closure/key。若日後快取 Manifest 整體可用性，須核同一 current generation 或所有 entries 的相符 exact compatibility 證據及 context，不能只核所選 Spell program。Catalog generation 提供一致性與 publication provenance，與 program 定義版本、actor epoch、P7 generation 及 P11 source epoch／version 分開。Hash、cache hit、Draft 可讀、compiler success 都不授權；cache／IR／diagnostics／derived index 不是 persistent truth，不寫回 definition／latest。

**只固定未來 Scope V 的資料契約**：在接受新的 root activation/creation 前，唯一 owner 從一個可證且 current 的 catalog generation 取得 exact root 和完整可達 closure，驗權限、可用性與當代能力、取得相同 key 的 immutable program，並在接受點前以 exact pins 保護整份 closure，非只 pin root。由 Manifest 進入時，另以 exact pin 或等效受證明的 root 保留 invocation 所需的 exact Manifest revision；這不使未選 Spell 自動成執行 root。若準備期間 generation／source／權限改變，舊 candidate 不得冒充新接受；無副作用地拒或依將來正式重取策略作新 attempt，不拼不同 generations。Admission 或 pin 實作須另行授權。

已接受 work、program、instance 與其 CreateSpell child 均沿用 captured exact closure／program。Reload、reconnect、Spell head 或 Manifest revision 的後續變更都不得引發重新解析 latest。後代以 parent 捕獲的 exact target 及同一次因果資源契約交付，不能以新 root 洗 budget、繞授權或創造第二個外部入口。未在 closure 的動態 target 不得以 lookup latest 補；其將來合法 caller／終態/ARM／計價／生存政策不在 Scope D。已存在 P5/P9 工作仍走現 legacy exact 路徑。

## 7. 跨 owner fork、Draft／raw 與 fail-closed

### 7.1 只允 closed-bundle fork

單 Spell 分享：以已授權且一致的 source binding 捕獲指定 exact Spell 與全部可達 deps。Manifest 分享：同理捕獲指定 exact Manifest revision、全 entries 與其 Spell transitive union；不是只匯出某一 active entry。若要匯出歷史組合，須有 matching historical generation 或完整受證的歷史 exact closure；不得用歷史 root 配今日 deps 冒稱歷史內容。兩條路都驗 completeness、權限、每一 body/family、Unknown、bounds、可驗 ID remap 與 raw 契約；不能先交裸指標，再向原作者補漏。Bundle 內的 exact mapping 是 export evidence，不是 receiver 永久 authoring refs。

Receiver 以自己的 owner scope 正式配發新 identities/revisions，對 bundle 內各 typed identity 做一對一 remap，保每 entry identity／order 的語意且不混淆 parent scope；只解析已知可合法改寫的引用。SCC/重複可達 target 不可展開為多份互相漂移的定義。新 authoring refs 指回 receiver identities，經其獨立 catalog 進同一 bounded publication。雙方各自可修改，sender 更新不改 receiver，receiver 不改 sender 或其他 fork。Unknown 可能藏 refs、bundle 缺依賴、含第三方 owner、無法證完整 remap 或超額時，僅保受權的有界材料／診斷，不建立可執行 fork；不得借 fork 名稱搬 legacy opaque slots。Provenance 不授 auto-merge／latest live link／跨 owner transaction。

### 7.2 版本、legacy 與 Unknown

- Logical family/version、per-envelope schema/version、physical carrier/version、Draft/version、authored revision 與 catalog generation 為獨立座標。讀取先判 family/version 與硬結構／尺寸，不能讓新外層欄位經舊 reader 靜默剝除。JSON／NBT 的 raw family、registry/context、typed location 與 defensive snapshot alias isolation 保留，mixed family 不轉寫成較方便的單一 tree；遷移只碰明授權 shell，不讀、hash、猜或搬 opaque payload／Unparsed slots。新 family 需按自身 typed location 及明示 migration policy，不以新 schema 號自動擴舊權限。
- Draft 中 Missing required、Unknown／raw、合法 `activation` absent、unresolved reference、待修不完整形式均可區分。Lossless 保留限受權且可在 bounds 內的 raw；超限按具名拒絕／隔離規則，不能宣稱 lossless 後靜默截斷。Known malformed 與 unsupported 不當 empty Ready，亦不因有 raw 就成立 formal publication。Gameplay Unknown 在獨立 Spell 的完整 closure 或整個 Manifest root 拒合法化，不跳一塊／一 entry 繼續；raw／有界診斷保留。Pure visual Unknown 獨立走既有 P8 fallback，不改 gameplay、不掩已發生 effect。
- 原 `SkillDocument.nodes`、position identity、1 Trigger＋1 Action、legacy `SkillId`／exact refs、Store/CAS/reclaim／player Attachment 行為及舊 canonical bytes 不改。Compatibility frontend 在未來 C 以 legacy exact ref 和受認的解析／驗證語意產共同 IR 的相容投影；不在 Scope D 改 P5/P9 執行，不放寬 P9/P10 starter／LKG、不重寫舊 revisions 或 goldens。新 editor 首期只讀 legacy 是保留的 IA 約束，非實作。通用轉換、exact P9 可證轉換、任何新 revision import/conversion 另需明授；沒有 `nodes[i]` 轉包進新 Spell／handler 的捷徑。

## 9. Bounds、責任與未來切片接受

唯一 limits authority 須按實際 shape 與可觀察工作推導，不擅分配新值、複製原限額或讓 family 擴充成乘數。所有加總、revision/generation 升序、分配前的 byte/length/count 算術須 checked；overflow/超額為有界具名拒絕，無部分 publication／sweep。

| 必須獨立定界的座標 | 最低證明要求 |

| owner/server families、retained histories/revisions、retired IDs、reservations | 每 Spell／Manifest/owner 與整體共享容量；current/rollback 必需 generation 與 pending batch 同時留存的峰值；不將 latest 自動等於最高 revision。 |
| activation/settings/handlers／blocks／operands、AST total nodes/depth、symbols/UTF-8/IDs | shape/depth、每 body 與 aggregate AST、每 event/handler、typed operand width；0..1 入口不代表其 child expression 成本有界。 |
