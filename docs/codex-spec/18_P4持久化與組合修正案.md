# P4 持久化、Attachment 與組合修正案

> 狀態：已核准的範圍限定修正案。
>
> 本案只修訂 P4 的 Skill Store persistence、玩家技能 Attachment、submission
> composition、recovery journal、offline roots 與 reconciliation 邊界。在本案明示的
> 範圍內，本案優先於較舊的凍結骨架、P3 scoped amendment、實作總規格與詳細工程步驟；
> P0～P3 以及未被本案明示修訂的規則繼續有效。若其他權威文件尚未同步而形成實質衝突，
> 必須停止受影響工作並回報，不得自行選邊。

## 1. 修訂範圍與既有真相

本案不重寫下列既有責任：

- P3-D Store 的 owner truth、quota counting、CAS、revision allocation 與 reclaim rules。
- P3-B2／P3-B3 的 resolution、payload migration、validation 與 runtime projection。
- `SkillDocument` 作為 revision 內容唯一真相；`ValidatedSkillDefinition` 仍是可重建的
  transient projection。
- Store 最大 retained revision 仍是 latest 與 allocator truth；Attachment pointer 不是。
- `gramarye_skill_definitions` carrier 只承載 P3-D Skill Store 與 P4 recovery journal。
  `RuntimePersistentStore`、Marker／Construct／Schedule 本體與其 persistence schema 不納入
  P4-A～P4-E，也不得偷渡進此 carrier；它們依後續既有功能階段或另行核准的排程實作。

## 2. P4 工程階段

### P4-A：Persistence format 與 migration bridge

- `SkillOwnerId` canonical Codec。
- family-tagged raw tree envelope。
- Store／History／Revision physical schema。
- exact encoded-byte ceilings。
- Store-envelope adjacent migration。
- 既有 skill migration plan 與 storage outer tree 接合。
- family-aware hydration。
- Store persistence bridge。
- 無 SavedData lifecycle，無 Attachment。

### P4-B：Overworld SavedData adapter

- 唯一 Overworld Store lifecycle。
- bounded compressed-file ingress 與 bounded NBT carrier ingress。
- custom non-fail-open load path。
- Ready／Quarantined state。
- prebuilt encoded carrier 與 dirty mapping。
- 無 Player Attachment。

### P4-C：Player Attachment

- permanent player skill data Attachment。
- Draft／latest／equipped／editor schema。
- custom total serializer 與 Attachment migration。
- Ready／Quarantined state。
- death／End clone policy。
- 無 Store commit composition。

### P4-D：Submission composition

- authenticated server principal 與 server SkillId mint consumer。
- fresh authorization 與 immutable quota snapshot。
- C1～C4 preparation。
- persistence preflight、Store commit、pending Attachment update journal。
- Attachment transition、typed composition outcome 與 crash recovery。
- 無 network。

### P4-E：Offline roots 與 reconciliation

- complete offline persistent root audit。
- rebuildable root index 與 completeness state。
- pointer reconciliation、reclaim composition 與 dirty mapping。
- 無 chunk force，無 background sweep。

各階段 absence assertion 只適用於該階段；後續階段依本節明示責任逐步加入。

## 3. Raw-family granularity

- `SkillDocument` 不具有單一 raw family invariant。同一 document、同一 node 可同時包含
  JSON 與 NBT raw subtrees；submission 不得只因 mixed family 而拒絕技能。
- Whole-document 或 whole-node 單一 family tag 不足。下列每一個 raw subtree 必須個別保存
  `RawTreeEnvelope`：
  - Trigger `DefinitionEnvelope.payload`；
  - Action `DefinitionEnvelope.payload`；
  - top-level `AppearanceDocument.Unparsed`；
  - 每一個 `AppearanceOverrideDocument.Unparsed`。
- 所有 `DefinitionEnvelope` payload 都必須加 tag，不得依 descriptor 當下是否存在決定。
- Raw subtree 不得跨 JSON／NBT family convert。

### RawTreeEnvelope V0

```text
RawTreeEnvelope {
  family: "json" | "nbt",
  registry_context: boolean,
  compressed_maps: boolean,
  data: byte[]
}
```

合法組合：

```text
json + registry_context=false + compressed_maps=false
json + registry_context=false + compressed_maps=true
json + registry_context=true  + compressed_maps=false
json + registry_context=true  + compressed_maps=true
nbt  + registry_context=false + compressed_maps=false
nbt  + registry_context=true  + compressed_maps=false
```

下列輸入非法：unknown family、NBT 配 `compressed_maps=true`、缺少必要欄位，或 `data`
超過 hard bound。

- `family` 只表示 serialized tree family。
- `RegistryOps` 不是第三種 family。`registry_context` 只表示 load 後需以當下 authoritative
  `HolderLookup.Provider` 重建 `RegistryOps`；Java registry provider identity 不持久化。
- `compressed_maps` 表示 JsonOps parent map compression policy。
- Definition payload 的 `data` 受既有 `MAX_RAW_PAYLOAD_BYTES` 限制；Unparsed appearance
  使用 §7 的 derived-equal `MAX_UNPARSED_APPEARANCE_BYTES`，不得建立平行 magic number。

### JSON data

- UTF-8，無 BOM，且有 byte bound。
- Canonical storage 可移除 whitespace 並採穩定 object key order。
- 必須保留 structural equality、array order，以及 numeric primitive 的 lexical/value contract；
  例如既有 `1.00` representation 不得被未經明示的 canonicalization 破壞。

### NBT data

- 使用鎖定 API 的 uncompressed arbitrary `Tag` bytes。
- 保留 exact Tag type、numeric type、list order 與 primitive arrays。
- 不經 JSON bridge。

## 4. Appearance persistence

Top-level persistent states 固定為：

```text
default | decoded | unparsed
```

Override persistent states 固定為：

```text
none | decoded | unparsed
```

- Top-level `Rejected` save as `default`。
- Override `Rejected` save as `none`／省略。
- Rejected 的 diagnostic、reason 與被拒 raw tree 均不得持久化。
- `Decoded` 使用 typed canonical appearance fields；`Unparsed` 使用其個別
  `RawTreeEnvelope`。
- Unknown appearance fields 仍依 P3-A 的刻意有損 canonical policy 剝除。

## 5. Persistent Store physical schema

### SavedData carrier

```text
{
  saved_data_schema_version: 0,
  store_blob: byte[],
  pending_attachment_updates_blob: byte[]
}
```

`pending_attachment_updates_blob`：

```text
{
  journal_schema_version: 0,
  entries: [...]
}
```

`store_blob` 是下列結構的 uncompressed NBT bytes：

```text
{
  store_schema_version: 0,
  history_entries: [byte[], ...]
}
```

`HistoryPersistentEnvelope`：

```text
{
  skill_id: UUID,
  owner: UUID,
  revision_entries: [byte[], ...]
}
```

`RevisionPersistentEnvelope`：

```text
{
  revision: int,
  document_encoding: "family_tagged_subtrees_v0",
  document_bytes: byte[]
}
```

Document storage tree 保留 `SkillDocument` logical outer shape：

```text
{
  schema_version,
  skill_id,
  revision,
  nodes,
  appearance
}
```

每個 node 的 trigger／action shell 保留 `type` 與 `schema_version`，`payload` 改為個別
`RawTreeEnvelope`；`appearance_override` 使用 §4 persistent state。

- Store、History、Revision 都以 `List` 保存，不先轉成 `Map`。Duplicate SkillId／revision
  必須原樣保留至 P3-D restore 判斷。
- Canonical save order：SkillId 依 UUID natural order，revision 依 int ascending。
- Route revision 與 document revision 刻意重複，供 restore pairing audit。
- Store schema 與 SkillDocument schema 彼此獨立。
- 不保存 latest cache、quota count、pins、validated projection、`ValidationResult`、Attachment
  pointer 或 reclaim report。
- V0 不新增 checksum。

## 6. Migration 唯一真相

不得建立第二個 skill migration registry／plan。

### Store envelope migration

- Adjacent edges、immutable plan、exact coverage。
- 負責 SavedData／Store／History／Revision／RawTreeEnvelope physical schema。

### Skill schema migration

- 繼續使用 P3-B1 既有且唯一的 `SkillMigrationPlan`。
- 作用於 NBT-family logical document outer tree。
- `RawTreeEnvelope.data` 保持 opaque bytes。
- 可修改 `SkillDocument` outer fields 與 `DefinitionEnvelope` shell，但不得解碼或轉換
  raw payload bytes。

### Payload migration

- 仍由 P3-B2 resolution 處理。
- P4 load 不得提前執行 descriptor payload migration。

`RawTreeEnvelope` schema 自身的變動屬 Store／storage migration，不屬 skill migration。
目前 production migration steps 為零，因此本契約調整不需要舊資料 migration。

## 7. Exact hard byte ceilings

下列值升格至唯一 `MagicSafetyCeilings` 位置：

```text
MAX_STORE_REVISION_ENTRY_ENCODED_BYTES = 1_114_112
MAX_SKILL_HISTORY_ENCODED_BYTES = 8_388_608
MAX_SKILL_STORE_ENCODED_BYTES = 67_108_864
MAX_STORE_QUARANTINE_ENTRY_BYTES = 1_114_112
MAX_STORE_QUARANTINE_TOTAL_BYTES = 16_777_216
MAX_PENDING_ATTACHMENT_UPDATES = 4_096
MAX_PENDING_ATTACHMENT_JOURNAL_ENCODED_BYTES = 1_048_576
MAX_SKILL_SAVED_DATA_CARRIER_ENCODED_BYTES = 69_206_016
MAX_SKILL_SAVED_DATA_FILE_BYTES = 73_400_320
MAX_UNPARSED_APPEARANCE_BYTES = MAX_RAW_PAYLOAD_BYTES
MAX_PLAYER_DRAFTS = 32
MAX_PLAYER_LATEST_STATES = 256
MAX_PLAYER_EQUIPPED_REFERENCES = 64
MAX_PLAYER_DRAFT_ENTRY_ENCODED_BYTES = 1_114_112
MAX_PLAYER_SKILL_ATTACHMENT_ENCODED_BYTES = 16_777_216
```

- Derived equal limits 必須引用既有常數，不複製 magic number。
- Exact maximum 合法，maximum + 1 拒絕；count ceiling 與 byte ceiling 同時成立。
- Unlimited quota 不能突破任何 technical byte ceiling。
- Encode 使用 bounded／counting output，不依理論最大值預配置巨大 buffer。
- Decode 先檢查 byte-array length，再解析內部 JSON／NBT。
- SavedData compressed file 先檢查檔案大小，再用 bounded `NbtAccounter` 限制解壓後
  carrier。
- Attachment byte bound 是 attachment-tag post-materialization boundary，不冒充 whole-playerdata
  parser bound。
- P4-A 必須以 dedicated-server heap benchmark 驗證 64 MiB Store 上限；benchmark 失敗時
  停止並提出權威數值修正，不得自行靜默調整。

## 8. Migration-before-restore

正式 load 順序：

```text
bounded raw file ingress
→ SavedData／Store envelope migration
→ per-history／revision length validation
→ per-document skill migration
→ family-aware raw hydration
→ current SkillDefinitionStoreSnapshot
→ SkillDefinitionStore.restore
```

- Migration 必須先於 restore。Restore 不呼叫 migration，也不猜 legacy format。
- Payload migration 不在 P4 load 執行。
- 任一 revision migration／decode 失敗使整個 Store fail closed，不建立 partial Store。
- 原始 bytes、migration intermediate 與 domain Store 均不得原地修改。
- Migration facts 不持久化。
- 只有 migration、decode、restore 全部成功後才可建立 `canonicalRewritePending`。
  Failure 資料不得 canonical rewrite。
- Outcome 必須區分 `StoreEnvelopeMigrationFailed`、`DocumentMigrationFailed`、
  `DocumentDecodeFailed`、`StoreRestoreRejected` 與 `Quarantined`。

四類測試必須各自存在，不得以單一 corruption test 取代：

```text
old schema
→ migration
→ current typed snapshot
→ restore success

same old document without migration
→ direct restore
→ UnsupportedDocumentSchema

missing migration edge／migration exception
→ migration failure
→ restore invocation count = 0

migration success + current snapshot domain corruption
→ restore typed rejection
→ not migration failure
```

## 9. SkillOwnerId Codec

- P4-A additive 新增唯一 canonical Codec：`SkillOwnerId ↔ UUID`。
- 必須重用 `SkillId` 目前使用的相同 UUID syntax helper 與 representation。
- 不建立 String owner domain ID、`PlayerId` 平行 wrapper、`StreamCodec` 或 player existence
  lookup。
- Codec 只驗 syntax，不判斷 owner 是否存在。

## 10. Derived encoded carrier 與 persistence preflight

Overworld adapter 的 Ready state 同時持有：

```text
SkillDefinitionStore domain truth
matching immutable encoded carrier
pending journal carrier
rewrite-pending state
```

Encoded carrier 可由 Store snapshot 重建，是 derived representation，不是第二 domain truth；
不得提供一般玩法查詢，只供 bounded save callback。

Commit preflight 在 live Store mutation 前完成：

1. Encode proposed revision／history delta。
2. 建立 prospective pending journal replacement。
3. 檢查 revision／history／store／journal／carrier 全部 byte bounds。
4. 完成所有一般可失敗工作。

Store typed failure 時丟棄 prospective carrier delta、不 dirty。Store commit 成功後才發布預建
carrier／journal replacement 並 mark dirty；commit 後不得首次執行一般 Codec。P4 不得為此重寫
owner／quota／CAS 裁決，carrier delta 只在 domain Store 回 `Committed` 後採用。

Reclaim 只移除既有 entries。`Completed` 且 reclaimed > 0 後，從 post-reclaim Store snapshot
過濾既有已編碼 revision entries，不重新跨 family encode raw documents，再建立 derived carrier
並 mark dirty。`Rejected` 或 `Completed` 且 reclaimed = 0 不修改 carrier、不 dirty。

## 11. SavedData 安全 load 與唯一 lifecycle

- Stable name 固定為 `gramarye_skill_definitions`。
- 唯一位置是 Overworld data storage；非 Overworld 維度取得同一 Overworld adapter。
- 不使用 static world singleton。
- NeoForge 標準 fail-open `computeIfAbsent` 不得作為技能 Store 的直接 deserializer 入口。

專用 loader：

1. 確認 primary `.dat` 是否存在。
2. 不存在時建立 empty Ready Store，初始不 dirty。
3. 存在時先檢查 compressed file size bound，再做 bounded NBT decompression，最後執行
   §8 load pipeline。
4. 成功後把 Ready adapter 安裝進 `DimensionDataStorage` cache。
5. 失敗時安裝 Quarantined adapter；不得建立 empty Store、不得 dirty、不得覆寫原檔。

Primary file unreadable 時不得自動把 `.dat_old` 無聲提升成 truth；`.dat_old` 只供未來
operator-assisted recovery。專用 loader 只能執行一次，不得自行讀取後再讓 `computeIfAbsent`
重讀。

Quarantined 狀態允許 dedicated server 繼續運作，但 Gramarye skill data subsystem 不可提交、
commit 或 reclaim；原檔保留且不靜默 reset。

## 12. Save callback 與 dirty matrix

SavedData save callback 只寫預建 immutable carrier；不得在 callback 第一次執行一般 Codec、
查詢 Store mutation、執行 migration、修改 Attachment 或執行 reclaim。

NeoForge async disk write 沒有成功 acknowledgement，因此 public 語意只能承諾：

```text
in-memory domain committed + persistence scheduled
```

不得宣稱 fsync durable、disk write 成功，或 Attachment 與 Store 已 durably atomic。

Dirty matrix 固定為：

| 事件 | Store SavedData dirty |
| --- | --- |
| Store `Committed` + journal published | 是 |
| Store typed failure | 否 |
| pin／close | 否 |
| reclaim `Rejected` | 否 |
| reclaim `Completed`, reclaimed = 0 | 否 |
| reclaim `Completed`, reclaimed > 0 | 是 |
| snapshot／read | 否 |
| journal 新增／更新／清除 | 是 |
| reconciliation 只改 Attachment | 否 |
| reconciliation 改 journal | 是 |
| load migration 全部成功 | Ready 後 rewrite pending + dirty |
| migration／decode／restore failure | 否 |
| Quarantined | 否 |
| Attachment schema migration | immutable replacement `setData` |

## 13. Player Attachment schema

建立獨立永久 Attachment：`gramarye:player_skills`。不得與 mana／cooldown 等不同死亡政策
資料混用。

V0：

```text
{
  attachment_schema_version: 0,
  drafts: [
    {
      skill_id: UUID,
      draft_encoding: "family_tagged_subtrees_v0",
      draft_bytes: byte[]
    }
  ],
  latest_states: [
    {
      skill_id: UUID,
      pointer: SkillReference?,
      mutation_generation: int
    }
  ],
  equipped_slots: [
    {
      slot: int,
      reference: SkillReference
    }
  ],
  editor: {
    selected_draft: UUID?,
    selected_node_index: int?
  }
}
```

- Owner 不持久化，由 authenticated player UUID 導出 `SkillOwnerId`。
- `mutation_generation` 範圍 `0..Integer.MAX_VALUE`，increment overflow fail closed。
- Disk collections 使用 `List` 保留 duplicate corruption；in-memory 可使用 immutable map。
- Draft read facts／`ValidationResult` 不持久化。
- Draft 有獨立 adjacent migration plan。
- Missing tag 建立 empty Ready Attachment；existing malformed tag 建立 Quarantined Attachment，
  不得視為 missing。
- Client 不是 truth；Attachment 不得配置 revision 或覆蓋 Store owner／latest。
- Custom total serializer 回 Ready／Quarantined union，不直接使用會 log-and-skip 的 partial
  Codec serializer。
- 永久資料使用 serialize + `copyOnDeath`；End return 不得手動 double-copy。
- 不自動 sync。
- Total byte cap 優先於個別 Draft cap；32 份 Draft 不表示每份都能同時達到個別最大值。

## 14. Submission composition

P4-D facade 位於 submission package，重用 package-private C1～C4 stages：

```text
authenticated server principal
→ derive SkillOwnerId
→ load authoritative Draft from own Ready Attachment
→ read current Store owner/latest
→ obtain one immutable SkillQuota snapshot
→ P3-C preparation
→ fresh owner/state recheck
→ persistence/journal preflight
→ Store commit with same quota snapshot
→ publish Store carrier + pending journal
→ dirty
→ Attachment immutable transition
```

- 不得接受 client 聲稱的 owner、authorization、quota、revision、Store state。
- `SkillIdSource` 的第一個 production consumer 必須使用：

```java
Objects.requireNonNull(source.nextSkillId(), "skillIdSource returned null")
```

- Draft 位於玩家 Attachment 內時才是跨 restart editing authority；transient mint return 不是
  credential。
- P3-C 固定 short-circuit 順序與 report merge 契約不變：read warnings → Draft schema →
  authorization → concurrency／exhaustion → completeness → B2／B3。合併來源 report 時先逐項
  加入 retained issues，再用 `ValidationCollector.inheritReportState` 傳播 `truncated`／
  `omittedError`。
- `SkillSubmissionPlan` 仍攜帶 owner／principal、precondition、proposed document與validated
  definition。Plan中的revision只是proposal；Prepared plan不是committed revision。

## 15. Composition outcome 與 report

新增獨立 composition outcome，不得把 `SkillSubmissionOutcome.Prepared` 當成 `Committed`。
至少表達：

```text
PreparationRejected
PersistenceCapacityRejected
CommitConflict
QuotaRejected
CapacityRejected
IdentityRejected
Committed
CommittedPendingAttachmentRecovery
SubsystemUnavailable
```

- 一旦流程取得 P3-C preparation report，後續 commit／quota／capacity／journal outcomes 都保留
  同一 warning-only report reference；不得重建、merge 或持久化 report。
- Pre-preparation failure 可沒有 report。
- Store commit result 不直接暴露 actual owner 或未授權 latest。
- `Conflict`／`IdentityRejected`／`RevisionExhausted` 的P3-C preparation report仍必須
  warning-only；identity rejection不得暴露技能存在性、latest或owner。

## 16. Store-first recovery journal

不採 Attachment-first。Journal V0：

```text
{
  journal_schema_version: 0,
  entries: [
    {
      owner: UUID,
      skill_id: UUID,
      expected_attachment_generation: int,
      target_attachment_generation: int,
      expected_pointer: SkillReference?,
      target_pointer: SkillReference
    }
  ]
}
```

不變量：

- Generation 非負，`target = expected + 1`；expected 為 MAX 時 fail closed。
- Stable key 是 `(owner, skill_id, target_generation)`。
- 每個 owner／skill chain 必須連續。
- 最多 4096 entries，total encoded bytes 最大 1 MiB。
- 不保存 `SkillDocument`、payload、`ValidationResult` 或 message。
- Pending target 是 external retention root。

安全順序：

```text
prebuild carrier／journal replacement
→ Store commit
→ publish carrier／journal
→ dirty
→ Attachment setData
```

Attachment 成功後不得立即假裝 durable 並清 journal。Journal 只能在後續 startup／login 從
已持久化 playerdata 重新讀取 Attachment，確認 generation 與 pointer 已等於 target 後清除並
dirty。若 disk 仍為 expected，重播 immutable Attachment transition、保留 journal，等待下一次
persistent readback；重播必須 idempotent。

## 17. Reconciliation

- Store owner／documents 是 truth。
- Attachment pointer 存在、Store reference 存在且 owner 匹配：保留，即使不是 Store latest。
- Pointer 不存在於 Store：修剪 Attachment，不改 Store。
- Owner mismatch：opaque 修剪，不洩漏 actual owner／latest。
- Journal target 有效：replay 或確認。
- Journal target 不存在或 owner 不符：typed reconciliation failure，不提升 pointer。
- 無 journal 的舊 pointer：不自動提升到 Store latest。
- Duplicate persisted route／slot：Quarantined 或 repair，不採 last-write-wins。
- 玩家移除 pointer：保留移除；Store 與 quota 不變。
- Orphan revision：不自動刪除、不釋放 quota。

## 18. Offline roots 與 rebuildable index

完整 persistent root 來源：

```text
player latest references
equipped references
pending journal targets
future SkillInstance
future Marker
future Construct
future Schedule
```

Store latest 已由 P3-D implicit root 保護，不重複加入。

- P4-E 執行 bounded read-only offline playerdata audit，不只掃 online players，不強制載入
  chunk。
- Unreadable／truncated／unknown source 使整體 `Incomplete`；無法證明 complete 時不得呼叫
  `Complete` reclaim。
- 採 rebuildable world-level root index；index 不是 truth，source truth 勝出，restart 後預設
  `Incomplete`。
- 只有全部 enabled source family audit 完成才可 `Complete`。未來 persistence feature 新增
  root 時，必須同步註冊 source family 與 completeness gate。
- Source/index conflict 先 reconcile。Missing Store root 不得靜默刪除後同輪重試。
- Capture 最多收集 MAX + 1，capture 與 reclaim 在同一 logic-thread call chain。
- `Complete` 不跨 tick 保存。
- 無 chunk force，無 background sweep。

## 19. Persistence failure model

P4 typed failures 至少區分：

```text
StoreEnvelopeMigrationFailed
DocumentMigrationFailed
DocumentDecodeFailed
StoreRestoreRejected
OuterSavedDataUnreadable
Quarantined
EncodedCapacityExceeded
SaveEncodeFailed
AttachmentDecodeFailed
AttachmentQuarantined
JournalCapacityExceeded
SubsystemUnavailable
```

Failure 只可保存 machine code、bounded numeric metadata、必要 typed route 與 bounded exception
class name；不得保存 exception message、stack trace、raw payload、whole Store bytes 或
`ValidationResult`。

Load failure 不 partial load、不 silent empty、不 dirty、不覆寫舊檔。

## 20. Implementation gates

- P4-A 開始前，本修正案必須已提交且遠端 CI 通過。
- P4-A 允許 `SkillOwnerId` Codec、raw／storage envelope、storage migration、persistence bridge
  與 byte ceilings；仍禁止 SavedData／Attachment。
- P4-B 允許 SavedData、bounded raw ingress／NBT、Ready／Quarantined adapter 與 dirty。
- P4-C 允許 Attachment、Draft／reference persistence 與 custom serializer。
- P4-D 允許 submission facade、composition outcome 與 journal。
- P4-E 允許 offline audit、root index、reconciliation 與 reclaim orchestration。

P4-A 第一個實作 Gate 必須證明：

```text
JSON、NBT、mixed-family document
都能在相同 family 下結構保存

且任一 migration／decode／restore failure
都不會安裝 partial 或 empty Store
```

## 21. Required tests

### P4-A

- JSON-family、NBT-family raw round-trip 與 mixed-family document round-trip。
- Plain／RegistryOps／compressed JsonOps rebind。
- Invalid family／context；無 cross-family conversion。
- Rejected appearance fallback persistence。
- 每個 byte bound 的 exact／+1，以及 count × byte bounds。
- §8 四類 migration／restore 測試對。
- Duplicate history／revision 保留至 restore。
- Dedicated-server heap benchmark 驗證 64 MiB Store ceiling。

### P4-B

- Absent file → empty Ready。
- Existing invalid file → Quarantined，not empty。
- Compressed file 與 decompressed carrier exact／+1。
- Overworld singleton；非 Overworld 取得同一 adapter。
- 完整 dirty matrix。
- Migration 後 canonical rewrite。
- Save callback 只寫 prebuilt carrier。
- Primary invalid 不自動提升 `.dat_old`。
- Restart round-trip。

### P4-C

- Empty default。
- Draft／latest／equipped／editor round-trip。
- Draft migration、duplicate／stale／bounds。
- Malformed existing tag → Quarantined；missing tag → empty。
- Death／keepInventory／End／logout-login。
- No auto sync。
- Mutation generation exact／overflow。

### P4-D

- Fresh authorization；quota snapshot 只取一次。
- `SkillIdSource` null fail-fast。
- Preparation conflict 與 commit conflict 分離。
- Carrier／journal preflight failure → zero Store mutation。
- Owner rejection opaque。
- Commit success、Attachment update success／failure。
- Journal cap、crash windows、readback-confirmed clear、replay idempotence。
- Report identity preservation。
- Async save 不宣稱 durable。

### P4-E

- Offline player roots；loaded-only → Incomplete。
- Unreadable source → Incomplete；future source family incomplete gate。
- MAX + 1 bounded capture；journal roots。
- Missing Store root → reconciliation。
- No chunk load。
- Reclaim `Rejected`／0／>0 dirty mapping。
- `Complete` 不跨 tick 重用。
