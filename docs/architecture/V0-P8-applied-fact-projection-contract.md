## Native fact pairing、唯一 caller 與 loss policy

1. 一次 P6 V0 invocation 正常返回後，唯一 root V0 adapter 在原 call stack 把 `P6RuntimeExecutionBridge.V0TerminalReceipt` 與同一 `P9V0WorldEffectHandoff` 交 `P8V0AppliedFactHandoff`。Exact receipt/guard 要對 server slot、V0 request、source V event、statement/release ordinal、carrier binding、native terminal identity、tick、context。P9 handoff 的 `consumeApplied` 為 one-shot，在顯示檢查之前消耗。錯誤、重複、capacity drop 都不能再次 offer。P6 返回的 receipt 不入 P8 queue。Handoff 單次 immutable material，無 live player、level、entity、port、P5 lease 或 lifecycle authority。P6 源 exception／Error 傳播時不以 presentation callback 補成功。
2. Spawn 只在完整 native add 確證 true 時可有 `CAST_RELEASE`。Reservation、constructor、原生索引的 partial insertion、false add、unknown、credential failure 與 force cleanup 均無 V0 applied token。OPEN 是 P5 on_create 的另行條件。已證完整 native add 但後續 OPEN 被 fence，可依同授權 context、tick 及本表 anchors 嘗試現有 offer，或由 P8 正常 drop。Offer 不提供 OPEN、`on_create` 或 ARM 資格。
3. Damage 只在 P9 exact call-local positive health/absorption applied 證據隨同 P6 confirmed primary receipt 時可有 `HIT`。Target claim／collision、`hurt` bool 與 incidental side effects 各自記錄。Exact applied 已成立而後續 stack 停止時保留前綴，P8 仍依 context/target/recipient guards。自然 `on_destroy`、close、native death callback 本身零投影。
4. Server scalar anchors 取 native spawn origin 或同一 claimed impact position、有限 Q15、exact dimension、catalog-neutral appearance 值、source A 的 attribution UUID、observed native IDs。A 必須在觀察時間有 exact roster、connection、server、level 才可給 optional source numeric ID 及 source-priority recipient。正常 logout 的原 A 不在線時，source ID 留空，source-priority eligibility 留空，budget attribution 維持原 UUID。B 按 ordinary watcher／proximity 獨立參選，不帶舊 A 的 connection epoch。HIT 只使用 exact native target 所持真 numeric ID／UUID。若當次已移除、不在該 exact level／index 或同 tick 消費時換成新物件，P8 可 drop，無補發。
5. V0 的 source/target witness 只在 P9/P6 call scope 比對原 capture。P8 staging 使用受管 P5 identity 的 non-recycled exact serial、original slot token、P8 server epoch，以及由原生 effect verified 的 numeric entity ID、UUID 和捕獲當下允許性。Drain 從 current level index 驗 ID、UUID、connection epoch、liveness、watcher/level/position，拒不符或不再合法。因鎖版 `Entity` 的 entity ID 使用原生程序全域 `AtomicInteger` 配發，封閉 fixture 證明正常生命期不重用。Wrap、nonce regression 或改 ID 的 fixture 令該呈現失證；不從 P8 再解析授權施法。既有 `P8RecipientSelector.currentConnected/remainsEligible` 440–501 擴窄 V0 scalar 檢查，legacy 路徑原樣。
6. Appearance 取 C 的當次 selected exact `SpellUnit.appearance`（`ScopeDProgram.java:24–36,63–64`）。V0 frontend authority 只接受 C 的 optional APPEARANCE `gramarye:v0_profile_triple` v1。該 descriptor 適用 category `gramarye:projectile`，三個 bounded TEXT fields `sound_profile`、`particle_profile`、`trail_profile` 映射 1 對 1，完整 `namespace:path`，每值至多既有 128 UTF-8 bytes，採非預設 namespace 的 `ResourceLocation` parse，不接受空白、動態參照或任意參數。Descriptor 缺席、未知或 triplet 驗證失敗，走既有整體純視覺 fallback，保原 C 輸入和 gameplay。其 scalar recipe 在 P5 裝載已編程序時投影至現有 visual-only `RuntimeNeutralAppearance`。已知型別用 `AppearanceDefinition`，缺／未知用既有 fallback 語意，最大 3 個 Profile selections，無 V0 event patch 或 raw 文檔。P8 在 offer 當次 capture 一個 active snapshot（141–145、176–201），以 `AppearanceSemantics.resolve`、`RuntimeNeutralAppearanceOverride.None.INSTANCE`、空 event patch 及`AppearanceParameterPolicy.none()` 運作，並呼既有 `verifyStoredProfileCosts`。既有 module defaults、missing/wrong channel fallback、缺 asset disable 的路徑適用（`AppearanceSemantics.java:34–59,97–114,241–268`）。工程 fixture 提供 absence、known、fallback 三類，呈現不足無法阻擋 P5、交易或 reward。
7. 同 slot、同 server tick／runtime tick 才消費，服務下一輪不得 carry。Reload epoch/context 失效丟舊 scalar queue，stop/slot teardown 丟棄。P8 own sequence 只供 packet/visual tie-break。Counter overflow 或 P8 費用不足皆 drop。`RuntimeException` 在 observer 邊界按既有 `recordObserverRuntimeException` 有界計數，P6 gameplay receipt 保持。`Error` 走現有 fatal policy，不能以 observer 成功遮蔽、重施、退款或保留待重試。
