## Bounded custody 與兩階段 native facts

P5 唯一 server slot 在 accepted lineage 內持一份 bounded exact A 見證與 W。Pre-spawn 起持 authentication、exact A／level 身分，透過 server thread 狀態把載體工作交給 exact binding。載體只有 `V0CarrierBinding`、opaque server-slot/generation/token、instance/lineage/binding ID、original level/dimension、inclusive deadline、spawn tick、固定運動資料與小型 native 狀態。P5 的 binding index 綁載體與 exact token 身分，setter 只接相同物件。A 的本體 reference 唯一放於該 lineage 的 exact witness，由 accepted work／child／載體持 bounded token；catalog lease、P6 bridge、P8 不持 A，native 資料只在受管 call stack 短借。原生 `Projectile.setOwner(A)` 的 native cached owner 由 vanilla 自己保留，server V0 `getOwner` 根本不呼原 `getOwner`。Client、legacy 仍走原各分支。

## Root 與 child 的工程幾何

**PROPOSED_CONTRACT**。Root admission 以 P7 既有 server sampling 的 pure 計算為模型。對原 exact A 取本次 server 捕獲的 eye 和有限 unit look，origin = eye + 0.10 × direction − (0, 0.10, 0)，以 ties-to-even Q15 編碼，重驗非零、原 level、loaded bounds、world border 和原 native permission。原幾何凍結在 P5 accepted work；release 重驗其 scope，沒有重新瞄準／向 B 採樣。初速形成於重新正規化的 Q15 × admitted `launch_step_milli / 1000.0`，再走 R1-03 的原生速度格點。P9 starter 原 1.5 不變。

Child 的唯一 geometry binder 取同次真 impact 的 captured position 與父載體 authoritative normalized direction，origin = impact position + 0.10 × direction，方向沿父 exact Q15。只在該 damage receipt 為成功且 exact A 仍在線、原 level loaded、scope/border/native permission 全可證時預配新 child，無掃描／新的 selector。Child 的 creator/cause 跟原 exact A，直接 parent 為 P5 父 instance；付款、deadline、source、input 限父血緣原值。Child release 等下一個合法 P5 drain，重新驗相同 geometry witness。Fixture 的標準成功讓直線前方有第二個預置 native target，但引擎本身不因 child 查上一目標或強制跳過它，仍用同一 native nearest/query。短尾可能因原 deadline 或原 target 的 invulnerability 合法停止。

**ENGINEERING_DERIVATION**。用原 native velocity fraction 格點。令 `raw = normalize(Q15) * (launch_step_milli / 1000.0)`，每軸 `q = (int)(rawAxis * 8000.0)`，`w=q/8000.0`。若用 native 原 encoder 重編 `w` 得到的 `(int)(w*8000.0)` 與 q 不同，先將 q 向零移一格，再重驗。R1 唯讀數值掃描涵蓋 [-8000,+8000] 的全部 16,001 個格點，在鎖定的 binary64 算式中未有兩個相鄰不穩定點，故一格修正便可核對穩定的非負/負對稱格點。算式一樣使用原向零截斷，非 finite、零全向量、來源出界或重驗失敗回具名 preflight decline。最小速度 .001 的非零向量至少有一軸 magnitude ≥.001/√3，即格點初值至少 4；一格修正不會全歸零。每軸對理想 raw 的誤差 <2/8000 block/tick，長度不增加。Server 持 `w`，client 既有 `ClientboundSetEntityMotionPacket` 24–33、62–72 解為同一 `w`；add packet 96–98、166–175 亦用同式。放棄任何 seed 對應未量化的 theoretical velocity 比較，驗收以實際 native packet decode 為座標。唯一新增 motion signature 是同類包內 `static Vec3 P9StarterProjectile.v0InitialVelocity(int directionXQ15,int directionYQ15,int directionZQ15,int launchStepMilli)`，JVM `(IIII)Lnet/minecraft/world/phys/Vec3;`，唯一 V0 server constructor 使用，無 retained fields、公開 override 或重載。從 constructor 真正寫入 motion 前便可作 deterministic validation，unexpected throwable 保原傳播。
